# Harness Roadmap

The seven handrails are the product surface in this alpha. A future harness may
select them, but it must not be used to hide weak primitives or recreate a
mandatory workflow.

## Current phase: validate primitives

- explicit invocation and direct entry for every skill;
- deterministic claim/review boundaries;
- separate development and claim evidence;
- formal Review Records for high-assurance claims;
- compact direct output and proportional continuity;
- safe isolation and rollback behavior;
- real-project dogfood with recorded rubric results.

## Preconditions for orchestration

Automation starts only after evidence shows:

1. which handrails repeatedly improve outcomes;
2. which selections cause needless ceremony;
3. which outputs another agent can consume reliably;
4. which transitions are safe to automate;
5. which repository/model/task signals calibrate autonomy;
6. where users consistently want control returned;
7. how failure and rollback remain legible.

## Harness constraints

A harness selection must be visible and record the chosen handrail, reason,
expected output, stop condition, skipped alternatives, authorization boundary,
and point where control returns. It must use the same smallest-safe-path rule as
a human and preserve explicit override.

No automatic orchestrator is included in the v0.1 alpha line.
